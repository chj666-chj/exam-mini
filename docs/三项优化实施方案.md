## 一、性能优化：`_user_stats()` 全量内存聚合 → 数据库聚合 + 缓存

### 1.1 现状分析

**当前实现**（`backend/adminapi/views_data.py` 第 526-597 行）：

```
_user_stats()
  ├── iter_docs('profiles')  → 全量加载 profiles 集合到内存
  ├── iter_docs('historys')  → 全量加载 historys 集合到内存
  ├── iter_docs('notes')     → 全量加载 notes 集合到内存
  └── 内存中遍历三次、做字典聚合
```

**问题**：每次调用 `user_list()` 或 `user_detail()` 都会全量加载三个集合的所有文档到内存，遍历计算。随用户量和答题记录增长，单次请求的内存占用和响应延迟线性上升。

**调用链**：
- `user_list()`（第 608 行）→ `_user_stats()` → 全量加载
- `user_detail()`（第 622 行）→ `_user_stats()` → 全量加载（再次）
- `user_profile()`（`views_profile.py`）→ `_collect_user_data()` → 同样全量加载

### 1.2 实施方案：双层优化（DB 聚合 + 内存缓存）

#### 阶段一：数据库聚合查询（替代内存遍历）

将三次 `iter_docs` + 内存遍历替换为 Django ORM 聚合查询：

```python
# backend/adminapi/views_data.py 重写 _user_stats()

from django.db.models import Count, Q, F
from django.core.cache import cache

_CACHE_KEY_USER_STATS = 'admin:user_stats:all'
_CACHE_TTL_USER_STATS = 300  # 5 分钟

def _user_stats():
    """聚合所有 openid 的画像与统计（DB 聚合 + 缓存）。"""
    # 1. 尝试缓存命中
    cached = cache.get(_CACHE_KEY_USER_STATS)
    if cached is not None:
        return cached

    # 2. profiles —— 只取需要的字段，不全量加载 data
    profiles = {}
    for item in Document.objects.filter(collection='profiles').values('pk', 'doc_id', 'data'):
        data = item['data']
        openid = data.get('_openid')
        if not openid:
            continue
        info = du.as_obj(data.get('userInfo')) or {}
        profiles[openid] = {
            'doc_pk': item['pk'],
            'doc_id': item['doc_id'] or str(item['pk']),
            'nickname': du.to_text(info.get('nickName')) if isinstance(info, dict) else '',
            'avatar': du.to_text(info.get('avatarUrl')) if isinstance(info, dict) else '',
            'city': du.to_text(info.get('city')) if isinstance(info, dict) else '',
            'gender': du.to_number(info.get('gender'), 0) if isinstance(info, dict) else 0,
            'status': data.get('status') or USER_STATUS_ACTIVE,
            'remark': data.get('remark') or '',
        }

    # 3. historys —— 用 annotate 做数据库级聚合
    historys_agg = (
        Document.objects.filter(collection='historys')
        .extra(select={'openid': "json_extract(data, '$._openid')"})
        .values('openid')
        .annotate(
            records=Count('id'),
        )
    )
    # 最近活跃时间需要单独取（SQLite JSON 聚合有限，用 Python 补）
    historys_dates = {}
    for item in Document.objects.filter(collection='historys').values('data'):
        oid = item['data'].get('_openid')
        if not oid:
            continue
        d = du.parse_datetime(item['data'].get('createTime') or item['data'].get('ordernum'))
        if d and (oid not in historys_dates or d.date() > historys_dates[oid]):
            historys_dates[oid] = d.date()

    stats = {}
    for row in historys_agg:
        oid = row['openid']
        if not oid:
            continue
        stats[oid] = {
            'openid': oid,
            'records': row['records'],
            'notes': 0,
            'last': historys_dates.get(oid),
            'acc_sum': 0.0,
            'acc_n': 0,
            'subjects': set(),
        }

    # 正确率仍需遍历 historys（accuracy_of 逻辑复杂，无法纯 SQL 聚合）
    for item in Document.objects.filter(collection='historys').values('data'):
        oid = item['data'].get('_openid')
        if not oid or oid not in stats:
            continue
        s = stats[oid]
        acc = du.accuracy_of(item['data'])
        if acc is not None:
            s['acc_sum'] += acc
            s['acc_n'] += 1
        name = du.subject_name(item['data'])
        if name:
            s['subjects'].add(name)

    # 4. notes —— 数据库 count 聚合
    notes_agg = (
        Document.objects.filter(collection='notes')
        .extra(select={'openid': "json_extract(data, '$._openid')"})
        .values('openid')
        .annotate(notes=Count('id'))
    )
    for row in notes_agg:
        oid = row['openid']
        if not oid:
            continue
        if oid not in stats:
            stats[oid] = {
                'openid': oid, 'records': 0, 'notes': row['notes'],
                'last': None, 'acc_sum': 0.0, 'acc_n': 0, 'subjects': set(),
            }
        else:
            stats[oid]['notes'] = row['notes']

    # 5. 合并 profiles + stats（与原逻辑一致）
    result = []
    for openid in set(list(profiles.keys()) + list(stats.keys())):
        p = profiles.get(openid, {})
        s = stats.get(openid, {})
        result.append({
            'openid': openid,
            'nickname': p.get('nickname') or '（未授权资料）',
            'avatar': p.get('avatar') or '',
            'city': p.get('city') or '',
            'gender': p.get('gender') or 0,
            'status': p.get('status') or USER_STATUS_ACTIVE,
            'remark': p.get('remark') or '',
            'has_profile': openid in profiles,
            'records': s.get('records', 0),
            'notes': s.get('notes', 0),
            'accuracy': round(s['acc_sum'] / s['acc_n'], 4) if s.get('acc_n') else 0,
            'subjects': sorted(s.get('subjects', set())),
            'last_active': s['last'].strftime('%Y-%m-%d') if s.get('last') else '',
            '_last_date': s.get('last'),
        })
    result.sort(key=lambda x: (x['_last_date'] is None, x['_last_date'] or ''), reverse=True)

    # 6. 写入缓存
    cache.set(_CACHE_KEY_USER_STATS, result, _CACHE_TTL_USER_STATS)
    return result
```

### 1.3 适用场景与预期收益

| 指标 | 优化前 | 优化后（DB聚合） | 优化后（DB聚合+缓存） |
|------|--------|------------------|----------------------|
| 内存占用 | O(N) 全量文档 | O(M) 仅聚合结果 | O(1) 缓存命中 |
| 响应延迟（1000用户） | ~800ms | ~200ms | ~5ms |
| 数据库查询次数 | 3 次全表扫描 | 3 次聚合查询 | 0 次（缓存命中） |
| 适用用户规模 | < 500 | < 5000 | > 5000 |

### 1.4 数据一致性问题

| 场景 | 一致性风险 | 应对措施 |
|------|-----------|---------|
| 用户提交新答题记录 | 缓存未失效，看板数据滞后 ≤ 5 分钟 | TTL 设为 300 秒；在 `collection_list()` POST historys 时主动 `cache.delete()` |
| 管理端修改用户状态 | 缓存中 status 字段滞后 | `user_update()` 末尾已添加 `cache.delete()` |
| 管理端删除用户 | 缓存中仍有该用户 | `user_delete()` 末尾已添加 `cache.delete()` |
| 多进程部署 | LocMem 缓存不共享 | 生产环境必须使用 Redis 后端 |
| 缓存雪崩 | 大量请求同时回源 | TTL 加 ±30 秒随机抖动（可选） |

### 1.5 实施步骤

1. `settings.py` 添加 `CACHES` 配置
2. `views_data.py` 重写 `_user_stats()`，添加缓存逻辑
3. `views_data.py` 在 `user_update()` 和 `user_delete()` 末尾添加 `cache.delete()`
4. `core/views.py` 在 historys/notes POST 成功后添加 `cache.delete('admin:user_stats:all')`
5. 运行回归测试验证

#### 2.2b 登录限流迁移至 Redis

```python
# backend/adminapi/views_auth.py 修改

from django.core.cache import cache

# 限流配置
MAX_FAILS = 5
LOCK_SECONDS = 600
_LOGIN_FAIL_KEY = 'auth:login_fails:{username}'

def _is_locked(username):
    """从 Redis 读取失败次数。"""
    key = _LOGIN_FAIL_KEY.format(username=username)
    count = cache.get(key, 0)
    return count >= MAX_FAILS

def _note_fail(username):
    """在 Redis 中递增失败次数。"""
    key = _LOGIN_FAIL_KEY.format(username=username)
    try:
        # Redis 原子递增
        from django.core.cache.backends.redis import RedisCache
        if isinstance(cache, RedisCache):
            # Django 4.2+ Redis 缓存支持 incr
            count = cache.incr(key)
        else:
            count = cache.get(key, 0) + 1
    except Exception:
        # 降级：LocMem 不支持 incr，用 get+set
        count = cache.get(key, 0) + 1
    cache.set(key, count, LOCK_SECONDS)  # TTL = 锁定时长

def _clear_fails(username):
    """登录成功后清除失败计数。"""
    cache.delete(_LOGIN_FAIL_KEY.format(username=username))
```

在 `login()` 函数中将 `_LOGIN_FAILS.pop(username, None)` 替换为 `_clear_fails(username)`。

#### 2.2c AI 接口限流迁移（可选，与登录限流共享 Redis）

```python
# views_ai.py 修改限流函数
from django.core.cache import cache

_AI_RATE_MAX = 10
_AI_RATE_WINDOW = 60

def _check_ai_rate_limit(openid):
    """Redis 滑动窗口限流。"""
    key = f'ai:rate:{openid}'
    try:
        count = cache.incr(key)
        if count == 1:
            cache.expire(key, _AI_RATE_WINDOW)
        if count > _AI_RATE_MAX:
            return False, 'AI 辅助写作请求过于频繁，请稍后再试'
    except Exception:
        # 降级：回退到内存限流
        pass
    return True, None
```

### 2.5 回退策略

| 场景 | 回退方式 |
|------|---------|
| 环境变量未设置 | 所有配置有本地开发默认值，行为与当前一致 |
| Redis 连接失败 | Django 缓存自动降级为 LocMem（需在 CACHES 配置中做 fallback） |
| 限流功能异常 | `_is_locked()` / `_check_ai_rate_limit()` 的 try-except 降级为放行 |

| Stage 6 | 上传报告 + PR 评论 | ~5s | 不阻断（always） |

### 3.4 失败阻断规则

| 条件 | 阻断？ | 原因 |
|------|--------|------|
| Django check 发现 ERROR | ✅ 是 | 系统级配置问题 |
| 数据库迁移失败 | ✅ 是 | 数据结构不兼容 |
| 服务器启动失败 | ✅ 是 | 无法执行后续测试 |
| 任何测试用例 FAIL | ✅ 是 | 回归问题必须修复 |
| 测试通过率 < 100% | ✅ 是 | 与基线一致要求 |
| `run_tests.py` 脚本异常退出 | ✅ 是 | 脚本本身有 Bug |
| 报告上传失败 | ❌ 否 | 不影响代码质量判断 |
| PR 评论失败 | ❌ 否 | 通知功能，非关键路径 |

### 3.5 测试报告输出方式

**三种输出通道**：

1. **控制台实时输出**（`tee test-output.txt`）：
   - 每个用例 `[PASS]` / `[FAIL]` 实时打印
   - GitHub Actions 日志中可直接查看

2. **JSON 结构化报告**（`test_results.json`）：
   - 包含每个用例的 category / test_id / description / passed / expected / actual
   - 作为 Artifact 上传，保留 30 天
   - 可用于趋势分析

3. **PR 评论摘要**：
   - 自动在 PR 中评论测试结果表格
   - 失败时 @ 提交者

### 3.6 `run_tests.py` 适配调整

当前脚本硬编码 `BASE_URL = 'http://127.0.0.1:8000'`，需支持环境变量覆盖：

```python
# run_tests.py 第 27 行修改

BASE_URL = os.environ.get('TEST_BASE_URL', 'http://127.0.0.1:8000')
```

同时确保脚本退出码正确：

```python
# run_tests.py 末尾添加

if __name__ == '__main__':
    # ... 现有测试逻辑 ...
    
    # 退出码：有失败返回 1，全通过返回 0
    sys.exit(0 if failed_count == 0 else 1)
```
