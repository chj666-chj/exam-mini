# P2 模块设计方案：自我测评 + 刷知识点

> 生成时间: 2026-09-09
> 约束: 功能定义、数据结构设计、交互流程，不进行代码编辑

---

## 模块间数据关联全景图

```
exam (考试)
 ├── subjects (章节, pid → exam._id)
 │    ├── knowledgePoints[] (章节内嵌知识点列表, 字符串数组)
 │    └── knowledgepoints (知识点主数据集合, examId → exam._id, pid → 父知识点)
 │         └── questions (题目, knowledgePointIds[] → knowledgepoints._id)
 │
 ├── 模拟考试 (examsetup → exam, 规则由 exam 文档定义)
 └── 自我测评 (assessment → exam, 规则由用户自定义)
      ├── 按知识点筛选 → questions.knowledgePointIds
      ├── 按难度筛选 → questions.difficulty
      └── 测评报告 → assessments 集合 (assessmentMode 标记)

historys (作答历史)
 ├── 普通练习: 无特殊标记
 ├── 模拟考试: examMode=true, score, duration
 └── 自我测评: assessmentMode=true, assessmentConfig, score, duration

notes (错题)
 └── questionId → questions._id (去重维度)
      └── knowledgePointIds → knowledgepoints._id (知识点错题统计)
```

## 一、自我测评模块

### 1.1 与模拟考试的定位区分

| 维度 | 模拟考试 | 自我测评 |
|------|---------|---------|
| **规则来源** | 考试文档预定义（exam.duration / passScore / questionTypes） | 用户自定义配置 |
| **题目范围** | 考试下全部章节，固定混合 | 用户可选：全考试 / 指定章节 / 指定知识点 |
| **题量** | 由考试文档定义（如 60+10+10=80 题） | 用户自由选择（10/20/30/50/自定义） |
| **时长** | 考试文档定义（如 150 分钟） | 用户自定义（不限时 / 10/30/60 分钟） |
| **难度** | 混合（模拟真实考试分布） | 用户可选难度范围（简单/中等/困难/全部） |
| **题型配比** | 考试文档定义 | 用户可选题型（单选/多选/判断/全部） |
| **即时反馈** | 不反馈，统一交卷判分 | 可选：统一交卷 or 逐题反馈 |
| **核心目的** | 检验考试通过率（及格/不及格） | 自我诊断薄弱环节，追踪进步趋势 |
| **结果报告** | 分数 + 及格判定 + 用时 | 分数 + 各维度分析 + 建议 + 历史趋势对比 |
| **可重复性** | 有限（同一考试规则固定） | 高（每次配置不同，灵活组合） |
| **入口** | 首页"模拟考试" → examsetup → exam | 首页"自我测评" → assessment → exam |

**一句话区分**：
> 模拟考试 = "按照真实考试规则，测试你能不能通过"
> 自我测评 = "按照你自己的需求，测试你在特定范围的水平"

### 1.2 功能定义

#### 1.2.1 测评配置页（assessment/index）

**核心交互**：用户进入后逐步配置测评参数，系统实时预估可抽题量。

| 配置项 | 控件类型 | 选项 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| 考试科目 | picker | 从 exam 集合加载 | 上次选择 | 选择考试范围 |
| 题目范围 | 单选 tag | 全部章节 / 指定章节 / 指定知识点 | 全部章节 | 决定筛选维度 |
| 章节多选 | checkbox 弹窗 | 从 subjects 加载 | 全选 | 仅"指定章节"时显示 |
| 知识点选择 | 树形选择器 | 从 knowledgepoints 加载 | 全选 | 仅"指定知识点"时显示 |
| 题量 | picker | 10/20/30/50/全部 | 20 | 受可抽题量上限约束 |
| 难度范围 | 多选 tag | 简单(1)/中等(2)/困难(3) | 全选 | 过滤 questions.difficulty |
| 题型 | 多选 tag | 单选/多选/判断 | 全选 | 过滤 questions.qtype |
| 时长 | picker | 不限时/10/20/30/60 分钟 | 30 | 0 = 不限时 |
| 反馈模式 | 单选 tag | 统一交卷 / 逐题反馈 | 统一交卷 | 决定 exam 页行为 |
| 随机顺序 | 开关 | 开/关 | 开 | 题目打乱 |

**实时预估**：用户每次修改配置时，系统查询题库估算可抽题量，显示"预计可抽取 N 题"。若不足目标题量则提示"当前条件仅有 N 题，不足 M 题"。

#### 1.2.2 测评答题流程

复用 exam 页，通过 URL 参数传递测评配置：

```
assessment/index
  → 抽题（按配置筛选 + 随机打乱 + 截取题量）
  → 存 storage（quiz_questions + quiz_mode + quiz_assessment_mode）
  → 跳转 exam?id=&mode=answer&assessmentMode=true&timeLimit=N&feedbackMode=unified|instant
```

exam 页根据 `assessmentMode` 参数行为：
- `feedbackMode=unified`：与模拟考试相同，不显示即时对错，统一交卷
- `feedbackMode=instant`：与普通答题相同，逐题即时反馈

#### 1.2.3 测评报告（examresult 增强）

交卷后跳转 examresult，携带 `assessmentMode=true` 参数，报告页显示：

| 报告模块 | 内容 | 数据来源 |
|---------|------|---------|
| 总分卡 | 得分 / 满分 / 得分率 | rightNum / total |
| 用时统计 | 考试用时 / 平均每题用时 | duration / total |
| 各题型分析 | 单选/多选/判断的答对率 | 按 qtype 分组统计 |
| 各难度分析 | 简单/中等/困难的答对率 | 按 difficulty 分组统计 |
| 各章节分析 | 每个章节的答对率 | 按 questions.examid → subjects.name 分组 |
| 薄弱知识点 | 答对率 < 60% 的知识点列表 | 按 knowledgePointIds 分组统计 |
| 学习建议 | 基于薄弱点的文字建议 | 规则引擎生成 |
| 历史对比 | 与上次测评分数对比（↑/↓） | 查询 assessments 历史记录 |

#### 1.2.4 测评历史趋势

在测评报告页底部或"我的"页面新增"测评历史"入口，展示：
- 折线图：历次测评得分率趋势
- 列表：每次测评的配置摘要 + 分数 + 日期
- 点击可查看历史报告详情

## 二、刷知识点模块

### 2.1 功能定义

#### 2.1.1 知识点体系架构

**三级层级结构**：

```
考试 (exam)
  └── 一级知识点 (level=1, 大类)
       ├── 二级知识点 (level=2, 子类)
       │    ├── 三级知识点 (level=3, 具体考点)
       │    └── 三级知识点
       └── 二级知识点
            └── 三级知识点
```

**示例**（软件设计师）：

```
软件设计师 (RK_RJJS)
  ├── 计算机系统基础 (level=1)
  │    ├── 数制转换与编码 (level=2)
  │    │    ├── 原码/反码/补码 (level=3)
  │    │    └── 浮点数表示 (level=3)
  │    ├── 校验码 (level=2)
  │    │    ├── 奇偶校验 (level=3)
  │    │    └── CRC循环冗余校验 (level=3)
  │    └── 存储系统 (level=2)
  │         ├── Cache映射方式 (level=3)
  │         └── 虚拟存储器 (level=3)
  ├── 操作系统 (level=1)
  │    ├── 进程管理 (level=2)
  │    │    ├── 进程状态转换 (level=3)
  │    │    └── PV操作与信号量 (level=3)
  │    └── ...
  └── ...
```

**设计决策**：利用现有 subjects 中已内嵌的 `knowledgePoints` 字符串数组作为初始数据源，将其提升为独立的 knowledgepoints 集合主数据。

#### 2.1.2 知识点列表页（knowledgepoint/index）

| 区域 | 内容 | 说明 |
|------|------|------|
| 顶部 | 考试 picker | 切换不同考试的知识点体系 |
| 树形展开区 | 三级知识点树 | 可折叠展开，每级显示题目数/掌握度 |
| 统计概览 | 总知识点数 / 已练习 / 未练习 / 薄弱(<60%) | 聚合统计 |

**每个知识点节点显示**：
- 知识点名称
- 关联题目数（`questionCount` 缓存字段）
- 掌握度色块：🟢 >=85% 精通 / 🔵 >=70% 熟练 / 🟡 >=60% 一般 / 🔴 <60% 薄弱 / ⚪ 0% 未练习
- 点击 → 进入该知识点的练习流程

#### 2.1.3 知识点练习流程

```
用户点击某知识点
  ↓
显示知识点详情卡片（名称/描述/题目数/掌握度/上次练习时间）
  ↓
选择练习模式：
  ├── 答题练习 → entry?id=&kpId=xxx（按知识点筛选题目）
  ├── 背题浏览 → entry?id=&kpId=xxx&mode=memorize
  └── 错题专项 → 加载该知识点下的错题 → note 页
  ↓
答题完成后更新该知识点掌握度
```

**题目筛选逻辑**：在 entry 页的 `loadQuestions` 中增加 `kpId` 参数支持：
- 查询 `questions.where({ knowledgePointIds: kpId })`
- 注意：由于 knowledgePointIds 是数组字段，需用"包含"查询（数组中包含某元素）

#### 2.1.4 知识点掌握度计算

**数据来源**：从 historys 集合中提取所有作答记录，按知识点维度聚合。

**计算逻辑**：
```
对于每个知识点 KP:
  1. 找到所有 knowledgePointIds 包含 KP._id 的题目 → questionSet
  2. 从 historys 中找到 items 包含 questionSet 中任意题目的记录
  3. 对每条历史记录，检查 score_arr 中对应题目的对错
  4. 统计该知识点下：
     - totalAnswered = 已作答题目数（去重）
     - totalCorrect = 答对次数
     - masteryRate = totalCorrect / totalAnswered * 100
  5. 掌握度分级：
     - >=85%: 精通
     - >=70%: 熟练
     - >=60%: 一般
     - >=1% 且 <60%: 薄弱
     - 0%: 未练习
```

**性能优化**：掌握度计算较重，建议在测评报告生成时或用户首次进入知识点页时计算一次，缓存到 `knowledgepoints.masteryCache` 字段。

#### 2.1.5 知识点薄弱分析

在知识点列表页和测评报告中展示薄弱知识点：

| 分析维度 | 展示形式 | 数据来源 |
|---------|---------|---------|
| 薄弱知识点排名 | 按掌握度升序列表 | knowledgepoints.masteryCache |
| 各知识点错题数 | 柱状图 | notes 按 questionId → knowledgePointIds 聚合 |
| 知识点练习进度 | 已练习/总题数 | historys.items ∩ questionSet |
| 建议练习顺序 | 优先推荐薄弱且题量多的知识点 | 掌握度 < 60% 按 questionCount 降序 |

### 2.2 核心数据结构

#### 2.2.1 新增集合：`knowledgepoints`

```json
{
  "_id": "KP_RJJS_001_002",
  "name": "原码/反码/补码",
  "pid": "KP_RJJS_001",           // 父知识点ID, 一级知识点 pid = exam._id
  "examId": "RK_RJJS",            // 所属考试
  "subjectId": "RK_RJJS_CH01",    // 所属章节（方便按章节筛选）

  "description": "原码、反码、补码的表示方法及零的唯一性",
  "sortWeight": 1,
  "questionCount": 3,             // 缓存: 关联题目数
  "masteryCache": {               // 缓存: 掌握度（定期更新）
    "totalAnswered": 2,
    "totalCorrect": 1,
    "masteryRate": 50,
    "level": "薄弱",
    "lastUpdated": "2026-09-09 22:30:00"
  },
  "createTime": "2026-09-09 10:00:00"

```

**一级知识点示例**：
```json
{
  "_id": "KP_RJJS_001",
  "name": "计算机系统基础",
  "pid": "RK_RJJS",
  "examId": "RK_RJJS",
  "subjectId": "RK_RJJS_CH01",
  "level": 1,
  "sortWeight": 1,
  "questionCount": 5

```

**ID命名规范**：`KP_{科目缩写}_{一级序号}_{二级序号}_{三级序号}`
- 一级: `KP_RJJS_001`
- 二级: `KP_RJJS_001_002`
- 三级: `KP_RJJS_001_002_003`

#### 2.2.2 questions 集合扩展

现有 questions 增加知识点关联字段：

```json
{
  "_id": "RK_RJJS_CH01_Q01",
  "title": "在计算机中，以下哪种编码方式...",
  "qtype": "single",
  "difficulty": 2,
  "examid": "RK_RJJS_CH01",
  "options": [...],
  // === 新增字段 ===
  "knowledgePointIds": ["KP_RJJS_001_002_001"],
  "knowledgePointNames": ["原码/反码/补码"],
  "tags": ["补码", "零的表示"]
}
```

**设计决策**：
- `knowledgePointIds`: 数组，一道题可关联多个知识点（如综合题）
- `knowledgePointNames`: 冗余存储名称，避免列表展示时逐个查 doc
- `tags`: 通用标签，可用于更灵活的筛选（如"高频考点"/"易错题"）

#### 2.2.3 从现有数据生成知识点主数据

现有 subjects 中已有 `knowledgePoints` 字符串数组（如 `["数制转换与编码", "校验码（奇偶/CRC）", ...]`），可自动生成 knowledgepoints 集合：

**生成脚本逻辑**：
```
for each subject in subjects:
  chapterKnowledgePoints = subject.knowledgePoints  // 字符串数组
  
  // 创建一级知识点（= 章节名称）
  KP_level1 = {
    _id: "KP_{examShort}_{chapterNum}",
    name: subject.name,
    pid: subject.pid,  // = exam._id
    examId: subject.pid,
    subjectId: subject._id,
    level: 1
  }
  
  // 为每个字符串创建二级知识点
  for idx, kpName in enumerate(chapterKnowledgePoints):
    KP_level2 = {
      _id: "KP_{examShort}_{chapterNum}_{idx+1:03d}",
      name: kpName,
      pid: KP_level1._id,
      examId: subject.pid,
      subjectId: subject._id,
      level: 2
    }
```

**题目标注逻辑**：
```
for each question in questions:
  subject = subjects.find(s => s._id == question.examid)
  // 简单方案: 将题目的 chapter 作为一级知识点
  // 进阶方案: 根据题目内容/标题关键词匹配二级知识点（需人工或AI辅助）
  question.knowledgePointIds = [对应的知识点ID]
  question.knowledgePointNames = [对应的知识点名称]
```

**标注策略**：
| 策略 | 说明 | 适用场景 |
|------|------|---------|
| 自动标注（章节级） | 将题目关联到其章节的一级知识点 | 全量题目，零成本 |
| 关键词匹配（考点级） | 根据题目标题/解析中的关键词匹配二级知识点 | 需构建关键词映射表 |
| 人工标注（精确级） | 管理后台逐题标注 | 高价值题目，精确分析 |
| AI辅助标注 | 调用 AI 分析题目内容自动标注 | 大批量标注 |

**推荐实施路径**：先自动标注到章节级（零成本全量覆盖），后续逐步精细到考点级。

### 2.3 关键交互流程

#### 2.3.1 知识点浏览与练习

```
用户点击"刷知识点"
  ↓
进入 knowledgepoint/index
  ↓
加载考试列表 → 选择考试 → 加载知识点树
  ↓
展示三级折叠树（名称 + 题数 + 掌握度色块）
  ↓
用户展开/折叠知识点节点
  ↓
点击某知识点 → 弹出详情卡片
  ├── 知识点名称/描述/题数/掌握度/上次练习时间
  ├── 答题练习 → entry?id={subjectId}&kpId={kpId}
  ├── 背题浏览 → entry?id={subjectId}&kpId={kpId}&mode=memorize
  └── 错题专项 → note?kpId={kpId}
  ↓
entry 页加载该知识点题目 → 答题流程
  ↓
答题完成 → 更新掌握度缓存
```

#### 2.3.2 entry 页知识点筛选增强

```
entry 页 onLoad:
  读取 options.kpId
  
loadQuestions:
  if kpId:
    查询 questions.where({ knowledgePointIds: kpId })
    // 注意: 数组包含查询, 需后端支持
  else:
    查询 questions.where({ examid: subjectId })
    // 现有逻辑
  
  后续处理不变（存 storage → 跳转 exam）
```

**后端适配**：Django Document API 需支持数组包含查询。当前 `where` 参数支持等值匹配，需扩展支持 `knowledgePointIds__contains=kpId` 类查询。

#### 2.3.3 后端 API 扩展需求

| API 变更 | 说明 | 优先级 |
|---------|------|--------|
| `knowledgepoints` 加入 ALLOWED_COLLECTIONS | 新集合白名单 | 必须 |
| where 查询支持数组包含 | `?knowledgePointIds__contains=KP_xxx` | 必须 |
| knowledgepoints.where({ pid }) 查询 | 支持按父ID加载子知识点 | 必须 |

## 三、两模块数据关联关系

### 3.1 自我测评 ↔ 知识点

```
自我测评配置
  ├── scope=knowledgepoints 时:
  │    用户选择知识点 → assessment.config.knowledgePointIds
  │    抽题: questions.where({ knowledgePointIds: { $in: selectedKpIds } })
  │
  └── 测评报告:
       results.byKnowledgePoint[] → 每个知识点的答对率
       results.weakPoints[] → 答对率<60%的知识点ID
       → 用户可点击薄弱知识点 → 直接跳转刷知识点模块
```

**关键关联**：测评报告的"薄弱知识点"直接驱动用户进入刷知识点模块，形成"测评 → 诊断 → 针对性练习 → 再测评"的闭环。

### 3.2 刷知识点 ↔ 错题

```
知识点练习:
  答题 → 答错 → addNote(含 questionId)
  notes.questionId → questions.knowledgePointIds
  → 可按知识点维度聚合错题统计

知识点错题专项:
  notes.where({ _openid, resolved: false })
  → 过滤出 knowledgePointIds 包含当前 kpId 的题目
  → 展示该知识点下的未掌握错题
```

### 3.3 知识点掌握度 ↔ 测评历史

```
掌握度计算:
  knowledgepoints.masteryCache
  ← 从 historys 聚合（按 knowledgePointIds 分组）
  ← 从 assessments.results.byKnowledgePoint 聚合

测评报告驱动:
  assessments.results.weakPoints
  → 更新对应 knowledgepoints.masteryCache.level = "薄弱"
  → 知识点列表页高亮显示薄弱知识点
```

### 3.4 数据流闭环

```
                    ┌──────────────┐
                    │  自我测评     │
                    │  (assessment) │
                    └──────┬───────┘
                           │ 生成测评报告
                           ▼
                    ┌──────────────┐
                    │  薄弱点诊断   │
                    │  weakPoints  │
                    └──────┬───────┘
                           │ 推荐练习
                           ▼
                    ┌──────────────┐
                    │  刷知识点     │
                    │  (knowledge) │
                    └──────┬───────┘
                           │ 针对性练习
                           ▼
                    ┌──────────────┐
                    │  错题记录     │
                    │  (notes)     │
                    └──────┬───────┘
                           │ 标记已掌握
                           ▼
                    ┌──────────────┐
                    │  掌握度更新   │
                    │  masteryCache│
                    └──────┬───────┘
                           │ 再次测评验证
                           ▼
                    ┌──────────────┐
                    │  自我测评     │
                    │  (assessment) │ ← 进步趋势对比
                    └──────────────┘
```

## 五、风险与约束

| 风险 | 影响 | 缓解方案 |
|------|------|---------|
| 数组包含查询性能 | knowledgePointIds 数组查询可能慢 | 后端添加索引；前端缓存题目列表 |
| 知识点标注工作量 | 60 道题需逐一标注 | 先章节级自动标注，后续逐步精细化 |
| 掌握度计算开销 | 需遍历 historys 全量数据 | 定期批量计算 + 缓存到 masteryCache |
| 测评报告复杂度 | 多维度统计逻辑复杂 | 在测评交卷时一次性计算存入 assessments.results |
| 前后端 where 查询扩展 | 数组包含查询非标准等值 | 后端 views.py 需增加 __contains 查询支持 |
