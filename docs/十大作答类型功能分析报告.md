## 一、顺序刷题

### 1. 功能匹配

**核心定位**: 按题目原始顺序逐题练习，从头到尾顺序作答，支持答题模式与背题模式切换。

**预期行为**:
- 加载某科目的全部题目，按 `sortWeight` 或题目编号顺序排列
- 逐题展示，用户选择后即时反馈对错（答题模式）
- 记录作答进度，支持断点续答
- 答完后生成历史记录，错题自动加入错题本

### 2. 字段审查

| 数据字段 | 当前状态 | 是否满足 | 说明 |
|---------|---------|---------|------|
| `questions.sortWeight` | ✅ 已有 | ⚠️ 未使用 | entry 页加载题目后未按 sortWeight 排序 |
| `questions._id` | ✅ 已有 | ✅ | 含 `CH{章节号}_Q{题号}` 可隐含顺序 |
| `questions.qtype` | ✅ 已有 | ✅ | 区分单选/多选/判断 |
| `questions.options` | ✅ 已有 | ✅ | 含 code/content/value |
| `historys.score_arr` | ✅ 已有 | ✅ | 记录每题用户答案 |
| `historys.items` | ✅ 已有 | ⚠️ | 仅存 _id 数组，无法判断每题对错 |

**缺失字段**:
- `historys.perQuestion` — 每题对错明细（目前需对比 score_arr 与 question.options 反推）
- `questions.sortWeight` 排序逻辑未在 entry 页实现

### 3. 能力评估

| 能力项 | 要求 | 当前状态 |
|--------|------|---------|
| 题目加载 | 按 examid 查询全部题目 | ✅ 已实现 |
| 顺序排列 | 按 sortWeight 或编号排序 | ❌ 未排序（依赖 API 返回顺序） |
| 模式切换 | 答题/背题模式 | ✅ entry 页支持 |
| 即时反馈 | 选择后显示对错 | ✅ exam 页已实现 |
| 断点续答 | 保存当前位置 | ✅ exam 页已实现（quiz_resume_{id}） |
| 历史记录 | 保存作答结果 | ✅ addHistory 已实现 |
| 错题记录 | 答错自动入错题本 | ✅ addNote 已实现 |

### 4. 实现状态: 🟡 部分实现

**已实现**: 基本答题流程完整，entry 配置页 → exam 答题页链路通畅，7 大功能模块已集成。
**差距**:
- entry 页 `loadQuestions` 未对题目按 `sortWeight` 排序，顺序刷题可能不是严格按编号顺序
- 跨科目（整个考试）的顺序刷题未实现，当前仅限单科目（单章节）范围内

### 5. 补充方案

| 补充项 | 类型 | 说明 |
|--------|------|------|
| sortWeight 排序 | 逻辑修改 | entry 页 loadQuestions 成功后增加 `.sort((a,b) => (a.sortWeight||0) - (b.sortWeight||0))` |
| 全考试顺序刷题 | 新功能 | 支持以 examId 加载该考试下所有科目的题目，合并后按章节+题号排序 |
| 跨科目进度 | 字段新增 | historys 增加 `examId` 字段，标记是单科目还是全考试练习 |

## 二、模拟考试

### 1. 功能匹配

**核心定位**: 模拟真实考试环境，限时作答，固定题量，完成后出具成绩报告。

**预期行为**:
- 从题库中抽取固定数量题目（如 50 题），可跨章节混合
- 设置考试时限（如 90 分钟），倒计时显示
- 考试中不显示即时对错反馈，统一交卷后判分
- 交卷后生成详细成绩单：总分、各题型得分、用时、错题列表
- 支持及格线判定（如 60 分及格）

### 2. 字段审查

| 数据字段 | 当前状态 | 是否满足 | 说明 |
|---------|---------|---------|------|
| `exam` 文档 | ✅ 已有 | ⚠️ | 仅有 name/description，缺少考试配置字段 |
| `questions` | ✅ 已有 | ✅ | 题目数据充足 |
| `historys` | ✅ 已有 | ⚠️ | 缺少考试模式标记、用时、分数 |

**缺失字段**:
- `exam.timeLimit` — 考试时限（分钟）
- `exam.passScore` — 及格分数
- `exam.totalScore` — 总分
- `exam.questionCount` — 考试题量（抽取数量）
- `exam.mixChapters` — 是否跨章节抽题（布尔）
- `historys.examMode` — 是否为模拟考试（布尔，区分普通练习）
- `historys.duration` — 考试用时（秒）
- `historys.score` — 考试得分
- `historys.passed` — 是否及格（布尔）

### 3. 能力评估

| 能力项 | 要求 | 当前状态 |
|--------|------|---------|
| 题目抽取 | 固定数量/全量/跨章节 | ❌ 当前加载单科目全部题目 |
| 倒计时 | 考试时限倒计时 | ❌ 未实现 |
| 统一交卷 | 不显示即时反馈 | ❌ exam 页答题模式有即时反馈 |
| 成绩计算 | 按题型/分值计分 | ❌ 仅统计 rightNum/errNum |
| 成绩报告 | 详细成绩单页面 | 🟡 examresult 页有基础统计 |
| 及格判定 | 对比及格线 | ❌ 未实现 |
| 交卷确认 | 弹窗确认 | ❌ 未实现 |
| 时间到自动交卷 | 超时自动提交 | ❌ 未实现 |

### 4. 实现状态: 🔴 未实现

**当前状态**: goExam 直接跳转 `exam?id={subjectId}`，进入普通答题流程，与顺序刷题无异。无考试时限、无题量限制、无成绩报告、无及格判定。exam 页的即时反馈机制与模拟考试"统一交卷后判分"的要求矛盾。

### 5. 补充方案

| 补充项 | 类型 | 说明 |
|--------|------|------|
| exam 配置字段 | 字段新增 | exam 文档增加 timeLimit/passScore/totalScore/questionCount/mixChapters |
| 模拟考试入口页 | 新页面 | 新建 `examsetup` 页，配置题量/时限后开始 |
| 倒计时组件 | 新功能 | exam 页增加 timer 逻辑，顶部显示倒计时 |
| 统一交卷模式 | 逻辑修改 | exam 页增加 `examMode` 参数，该模式下禁用即时反馈，统一交卷判分 |
| 成绩报告页 | 页面增强 | examresult 页增加分数/及格判定/各题型统计/用时 |
| 自动交卷 | 新功能 | 倒计时归零自动触发 goNext → addHistory → goResult |
| historys 扩展 | 字段新增 | 增加 examMode/duration/score/passed 字段 |
| 跨章节抽题 | 逻辑修改 | 加载 examId 下所有 subjects 的 questions，随机抽取 N 题 |

**预期行为**:
- 展示当前考试下所有章节列表
- 每个章节显示题目数量、上次练习进度、正确率
- 选择章节后进入答题配置 → 答题流程
- 记录每个章节的练习进度

### 2. 字段审查

| 数据字段 | 当前状态 | 是否满足 | 说明 |

| `questions` | ✅ 已有 | ✅ | examid 关联 subject._id |
| `subjects.questionCount` | ❌ 缺失 | ⚠️ | 当前动态查询，无缓存字段 |
| `subjects.progress` | ❌ 缺失 | ⚠️ | 无章节级进度记录 |

**缺失字段**:
- `subjects.questionCount` — 缓存题数（避免每次逐章节查询）

## 四、我的错题

### 1. 功能匹配

**核心定位**: 汇总所有答错的题目，支持回顾与重新作答，帮助针对性攻克错误。

**预期行为**:
- 按时间/科目/章节维度展示所有错题
- 支持只读回顾模式（查看题目+正确答案+用户答案）
- 支持重做模式（对错题重新作答）
- 统计错题趋势：本周错题数、已掌握/未掌握
- 支持错题标记为"已掌握"，从错题本移除

### 2. 字段审查

| 数据字段 | 当前状态 | 是否满足 | 说明 |
|---------|---------|---------|------|
| `notes.ordernum` | ✅ 已有 | ✅ | 按场次分组 |
| `notes.question` | ✅ 已有 | ✅ | 存储完整题目对象 |
| `notes.userAnswer` | ✅ 已有 | ✅ | 用户答案 |
| `notes.createTime` | ✅ 已有 | ✅ | 记录时间 |
| `notes.questionId` | ❌ 缺失 | ⚠️ | 未单独存储题目 ID，不利于去重 |
| `notes.examid` | ❌ 缺失 | ⚠️ | 未存储科目 ID，无法按科目筛选 |
| `notes.resolved` | ❌ 缺失 | ⚠️ | 无法标记"已掌握" |
| `notes.retryCount` | ❌ 缺失 | ⚠️ | 无法统计重做次数 |

**缺失字段**:
- `notes.questionId` — 题目唯一标识（去重/反查）
- `notes.examid` — 科目 ID（按科目筛选错题）
- `notes.resolved` — 是否已掌握（布尔，已掌握的不再展示）
- `notes.retryCount` — 重做次数

### 3. 能力评估

| 能力项 | 要求 | 当前状态 |
|--------|------|---------|
| 错题列表 | 展示所有错题 | 🟡 按场次分组展示，无单题列表 |
| 只读回顾 | 查看正确答案对比 | ✅ note 页已实现 |
| 重新作答 | 对错题重做 | ❌ note 页为只读模式，无作答功能 |
| 按科目筛选 | 过滤特定科目错题 | ❌ 未实现 |
| 错题去重 | 同一题多次答错只记一次 | ❌ 每次答错都新增 notes 记录 |
| 标记已掌握 | 移除已掌握错题 | ❌ 未实现 |
| 错题统计 | 趋势/分布 | ❌ 未实现 |

### 4. 实现状态: 🟡 部分实现

**当前状态**: goWrong → `switchTab wrong/index`，wrong 页查询 notes 按 ordernum 分组展示，点击进入 note 页只读回顾。

**差距**:
- 仅支持按场次回顾，无单题级列表
- 无重新作答功能
- 无按科目/难度筛选
- 无错题去重（同一题多次答错产生多条 notes）

## 七、乱序刷题

### 1. 功能匹配

**核心定位**: 将题目顺序打乱后练习，避免记住位置而非理解内容，检验真实掌握程度。
