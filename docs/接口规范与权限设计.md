# 考试宝 · 接口规范与权限设计

> 覆盖两套接口体系：
> 1. **小程序端兼容层** `/api/*` —— 复刻微信云开发语义，前端页面无需大改即可运行；
> 2. **Web 管理端** `/api/admin/*` —— REST 风格，统一响应信封、错误码、令牌鉴权与 RBAC 权限。

---

## 一、小程序端功能模块与数据流分析

### 1.1 功能清单与接口需求

| # | 功能模块 | 页面 | 触发的动作 | 数据集合 | 接口需求 |
|---|---------|------|-----------|---------|---------|

| 6 | 单题模式答题 | exam | 逐题取题、错题入笔记、交卷写记录 | `questions`、`notes`、`historys` | `GET .../questions/<id>/`、`POST .../notes/`、`POST .../historys/` |

### 1.2 关键数据流

```
启动 → login(openid) → 缓存 openid
首页 → exam 列表 → 科目 → 题序(arr)
     ├─ 答题 → 提交 → notes(错题) + historys(记录)
     └─ 我的 → historys(_openid) → review / note 重做
```

### 1.3 集合别名与兼容

原仓库存在新旧两套命名，兼容层统一映射：

| 前端写法 | 实际集合 |
|---------|---------|
| `question` | `questions` |
| `history` / `historys` | 各自独立（旧版 `history` 为 score 页写入） |
| `test` / `record` | 独立集合（旧版模式） |

## 二、统一响应规范

### 2.1 小程序兼容层（`/api/*`）

保持微信云开发返回语义，页面代码零改动：

| 接口 | 返回 |
|------|------|
| `POST /api/login/` | `{"openid": "..."}` |
| `GET /api/collections/<c>/` | `{"data": [...]}` |
| `GET /api/collections/<c>/?count=1` | `{"total": n}` |
| `GET /api/collections/<c>/<id>/` | `{"data": {...}}` |
| `POST /api/collections/<c>/` | `{"_id": "..."}` |
| `PUT /api/collections/<c>/<id>/` | `{"_id": "..."}` |
| `DELETE /api/collections/<c>/<id>/` | `{"deleted": true}` |

错误响应在保留 `error` 字段的基础上，追加与管理端一致的 `code` / `message`：

```json
{ "code": 40301, "message": "未登录：写入该集合需要先调用 login 获取 openid", "error": "..." }
```

### 2.2 管理端（`/api/admin/*`）

统一信封：

```json
{ "code": 0, "message": "ok", "data": {} }
```

分页数据固定结构：

```json
{ "code": 0, "message": "ok", "data": { "list": [], "total": 100, "page": 1, "page_size": 20, "total_pages": 5 } }
```

### 2.3 错误码

| code | HTTP | 含义 | 前端处理 |
|------|------|------|---------|
| 0 | 200 | 成功 | — |
| 40001 | 400 | 参数错误 / 请求体非法 / 方法不支持（405） | 提示 message |
| 40101 | 401 | 未登录或令牌缺失 | 清令牌 → 跳登录页 |
| 40102 | 401 | 令牌过期 | 同上 |
| 40103 | 401 | 账号或密码错误 | 提示 |
| 40301 | 403 | 无权限（缺少权限点） | 提示 |
| 40302 | 403 | 账号已停用 | 提示 |
| 40401 | 404 | 资源或接口不存在 | 提示 |
| 40901 | 409 | 资源冲突（如账号重复、_id 重复） | 提示 |
| 50001 | 500 | 服务内部错误 | 提示 |

> 未匹配的 `/api/` 路径由兜底路由返回 `40401` JSON（开发/生产一致）；
> 方法不允许返回 HTTP 405 + `40001`；未捕获异常返回 HTTP 500 + `50001`。

### 2.4 请求参数规范

- 分页：`page`（从 1 开始）、`page_size`（默认 20，超过 200 收敛为 200）
- 关键字：`keyword`
- 排序：`ordering`（`pk` / `-pk` / `created_at` / `-created_at`）
- 写操作：`Content-Type: application/json`，body 为 JSON 对象
- 鉴权：`Authorization: Bearer <token>`（兼容 `X-Admin-Token`）
- 小程序写操作：`X-Openid: <openid>`
- 令牌有效期由 `settings.ADMIN_TOKEN_TTL_HOURS` 控制（默认 12 小时）

### 2.5 写操作业务校验

全量写入（POST/PUT）校验必填字段，局部更新（PATCH）仅校验出现的字段：

| 资源 | 必填字段 | 业务规则 |
|------|---------|---------|
| exams | `name` | 名称不能为空 |
| subjects | `name` | 名称不能为空 |
| questions | `title` `examid` `options` | 题干/科目编号非空；options 为 ≥2 个选项的数组，每个选项必须有 `code` 和 `content`，且至少一个选项 `value=1`（正确答案） |
| records / notes | — | 无强制字段 |
| admins（创建） | `username` `password` | 密码 ≥6 位，账号唯一 |
| roles | `permissions` | 必须是合法权限点；superadmin 必须拥有全部权限 |

违反时返回 `40001` 及具体提示。归属字段 `_openid` 不可被客户端改写（更新时服务端强制还原）。

## 三、权限模型（RBAC）

### 3.1 权限点

| 分组 | 权限点 |
|------|--------|
| 数据看板 | `dashboard.view` |
| 用户管理 | `user.view` `user.manage` |
| 考试管理 | `exam.view` `exam.manage` |
| 科目管理 | `subject.view` `subject.manage` |
| 题目管理 | `question.view` `question.manage` `question.import` |
| 答题记录 | `record.view` `record.manage` |
| 错题笔记 | `note.view` `note.manage` |
| 标签管理 | `tag.view` `tag.manage` |
| 数据浏览 | `data.view` |
| 系统管理 | `admin.view` `admin.manage` |

### 3.2 内置角色

| 角色 | 权限 |
|------|------|
| `superadmin` 超级管理员 | 全部权限 |
| `operator` 运营 | 除系统管理外的全部读写 |
| `viewer` 只读访客 | 全部只读 |

角色权限可在后台「系统管理 → 角色权限」调整（超级管理员角色不可修改）。

### 3.3 鉴权链路

```
请求 → Token 解析 → 账号状态校验 → 权限点校验 → 业务处理 → 操作日志
```

- 令牌有效期默认 12 小时（`settings.ADMIN_TOKEN_TTL_HOURS` 可调），修改密码会强制其它端重新登录
- 连续 5 次密码错误锁定 10 分钟（进程内计数）
- 所有写操作记录到 `OperationLog`（账号、动作、对象、IP、时间）

### 3.4 小程序端数据权限

对齐云开发「仅创建者可写」的集合权限：

- 私有集合：`historys` `notes` `history` `test` `record` `profiles`
- 读：公开（保证首屏与演示数据可见）
- 写：必须携带 `X-Openid`，且更新/删除时 `_openid` 必须与请求者一致
- **停用联动**：管理端把用户置为「停用」后，该 openid 在小程序端的所有写入
  立即被拦截（`40301`），读操作不受影响；前端 `utils/api.js` 在写操作前
  若本地无 openid 会自动补一次 login 再重试
- 开关：`settings.EXAM_REQUIRE_OPENID_FOR_WRITE`（默认开启）

### 标签管理

| 方法 | 路径 | 权限 |
|------|------|------|
| GET/POST | `/api/admin/tags/` | `tag.view` / `tag.manage` |
| GET/PUT/DELETE | `/api/admin/tags/<id>/` | `tag.view` / `tag.manage` |
| POST | `/api/admin/tags/bind/` | `tag.manage`（批量绑定） |
| GET/POST | `/api/admin/questions/<id>/tags/` | `tag.view` / `tag.manage`（题目标签） |

标签分类：`knowledge`（知识点）· `difficulty`（难度）· `qtype`（题型）。每题可关联多个标签，支持按标签筛选题目。

### 批量导入

| 方法 | 路径 | 权限 |
|------|------|------|
| GET/POST | `/api/admin/questions/import/` | `question.import` |
| GET | `/api/admin/questions/import/<job_id>/` | `question.import` |

**POST 参数**：`{items: [...], async: bool, on_duplicate: "skip"|"overwrite"|"error", default_examid: "001001", tags: [tag_id...]}`

- 单次最多 500 道题目
- `async=true` 时后台线程处理，前端轮询 `GET .../import/<job_id>/` 获取进度
- 重复检测键：`examid + 归一化题干` 或显式 `_id`
- 返回逐题结果：`{index, status, _id, title, qtype, errors}`

### 图片上传

| 方法 | 路径 | 权限 |
|------|------|------|
| POST | `/api/admin/upload/` | `question.manage` |

`multipart/form-data` 上传图片，返回 `{url, filename, size}`。图片存储在 `media/questions/` 下，通过 `/media/` 静态服务访问。用于题目正文 Markdown 中的图片插入。

### AI 判卷（预留）

| 方法 | 路径 | 权限 |
|------|------|------|
| POST | `/api/admin/questions/<id>/ai-grade/` | `question.manage` |

**请求**：`{answer_text: "考生作答", rubric?: "覆盖评分要点"}`

当前返回 `{graded: false, supported: false, reason: "ai_service_not_configured"}`，接口已预留，配置判卷服务后自动生效。

## 五、题目数据结构（六种题型）

题目仍以 `Document(collection='questions')` 存储，扩展字段如下：

| 字段 | 说明 |
|------|------|
| `qtype` | `single` / `multiple` / `judge` / `fill` / `qa` / `multi_part` |
| `content_md` | 题目正文 Markdown（支持 `**加粗**`、`==高亮==`、`![图片](url)`、列表等） |
| `title` | 纯文本摘要（由 Markdown 自动生成，兼容小程序列表展示） |
| `images` | 从正文提取的图片地址列表 |
| `options` | 选项（single/multiple/judge 使用），每项 `{code, content, value}` |
| `blanks` | 填空题各空可接受答案列表（二维数组） |
| `answer_md` | 问答题参考答案（Markdown） |
| `sub_questions` | 一题多问的子题数组（递归结构，深度 1） |
| `ai_grading` | AI 判卷预留：`{enabled, rubric, model, max_score}` |
| `tag_ids` | 绑定的标签 ID 列表（镜像存储，权威数据在 QuestionTag 表） |
| `examid` | 所属科目编号（必填） |

兼容旧字段：`typename`（题型中文名）、`typecode`（题型编码）、`title`（作为 Markdown 源的兼容写法）。
