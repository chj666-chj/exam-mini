# AI 模型配置说明（多模型自定义接入）

> 适用范围：管理后台（`web-admin`）+ 小程序端（`miniprogram`）。
> 目标：用户可自定义接入真实 LLM Key、添加多个模型，并在实际使用时自由选择调用哪个模型。

---

## 一、配置方式

模型配置统一存储在服务端 `ai_models` 集合，分为两类作用域：

| 作用域 | 维护者 | 可见范围 | 用途 |
|--------|--------|----------|------|
| `global`（全局模型） | 管理员 | 全部用户 | 平台统一提供的模型，所有用户可直接选用 |
| `user`（我的模型） | 小程序用户 | 仅本人 | 用户用**自己的 API Key** 接入的模型 |

### 1.1 管理端配置（全局模型）

入口：**管理后台 → AI 配置**。页面自上而下为四个区块，形成「新增模型 → 自动同步列表 → 功能级选择」的闭环：

| 区块 | 作用 |
|------|------|
| ① 全局设置 | AI 总开关、全局系统提示词；折叠区为「兼容配置（旧版单配置）」 |
| ② **AI 模型配置** | **新增 / 编辑模型**的表单（模型名称、类型、API 地址、API Key、模型标识、参数） |
| ③ **AI 模型列表** | 已配置模型的概要表格，支持 **编辑 / 测试 / 设为默认 / 删除** |
| ④ **AI 功能级配置** | 为每个功能模块**下拉选择**要调用的模型（选项来自 ③ 的模型列表） |

新增模型流程：

1. 在「**AI 模型配置**」中填写：**模型名称**、**类型**（服务商，选择后自动带出接口地址与候选模型名）、**API 地址**、**API Key**、**模型标识**，并可按需调整 Temperature / Max Tokens / 启用 / 备注；
2. 点击「**保存并加入模型列表**」→ 保存成功即**自动同步**到下方「AI 模型列表」，无需额外操作；
3. 在「AI 模型列表」中可继续 **编辑 / 测试 / 设为默认 / 删除**（点「编辑」会把该行载入上方表单，表单顶部出现「编辑中」标记）。

> 列表中的 API Key 一律**脱敏展示**（`****` + 末 4 位）。编辑时保持脱敏值不变即表示 **保留原 Key**，填入新值则覆盖。
> 列表首条模型会**自动成为全局默认模型**，后续可用「设为默认」调整。

#### 功能级：为每个功能模块选择模型

在「**AI 功能级配置**」中，每个功能卡片都提供「**调用模型**」下拉选择器，选项来自「AI 模型列表」中已配置的模型（已禁用的模型不可选）。

- **留空** = 使用默认（用户默认 → 全局默认）；
- 选择某个模型 = **该功能的 AI 调用固定使用该模型**（如「AI 智能判卷」用高精度模型、「AI 自动标签」用轻量模型）；
- 卡片底部「当前使用：…」实时展示该功能实际会调用的模型，便于核对；
- 同时可单独设置该功能的 `Temperature` / `Max Tokens` 与启用开关；
- 修改后点击页面右上角「**保存配置**」写入。

各功能配置的 `model` 字段既支持存**模型 ID**，也兼容历史遗留的**模型标识 / 名称**字符串（自动按标识匹配到已登记模型）。

### 1.2 小程序端配置（我的模型）

入口：**小程序 → 我的 → AI 配置**（页面 `pages/ai-config/index`）

1. 顶部「模型配置说明」展示数量上限与生效时机；
2. 点击「+ 新增我的模型」，选择服务商（自动带出该服务商的默认接口地址与常见模型名，可手动修改）；
3. 填写自己的 API Key 并保存。

> 小程序端同样可看到管理员配置的**全局模型**，但全局模型仅可「测试 / 设为我的默认」，不可编辑或删除（由管理员统一维护）。

### 1.3 服务商预设

内置常见 OpenAI 兼容服务商，选择后自动填充 API 地址与候选模型名：

| 服务商 | 默认 API 地址 |
|--------|---------------|
| OpenAI | `https://api.openai.com/v1/chat/completions` |
| DeepSeek | `https://api.deepseek.com/v1/chat/completions` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` |
| Moonshot 月之暗面 | `https://api.moonshot.cn/v1/chat/completions` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4/chat/completions` |
| 自定义 | 需自行填写（须兼容 OpenAI Chat Completions 协议） |

## 二、可添加数量

数量上限由 `settings.AI_MODEL_LIMITS` 控制，默认：

| 作用域 | 默认上限 | 说明 |
|--------|----------|------|
| 全局模型 | **10 个** | 管理员可维护的全局模型总数 |
| 我的模型 | **5 个** | 每个小程序用户可添加的自有模型数 |

- 达到上限后「新增」按钮禁用；后端二次校验，超限返回 `模型数量已达上限（最多 N 个）`。
- 单个用户**可选用**的模型总数 = 全局模型数 + 自有模型数。
- 调整上限：修改 `backend/backend/settings.py` 的 `AI_MODEL_LIMITS`，重启后端生效。

## 三、切换与选择入口

### 3.1 选择「我的默认模型」

| 端 | 入口 | 说明 |
|----|------|------|
| 小程序 | AI 配置页 → 目标模型卡片 → 「设为我的默认」 | 可把**自有模型**或**任意全局模型**设为个人默认 |
| 管理端 | AI 配置 → 模型列表 → 「设为默认」 | 设置**全局默认模型**（影响所有未指定模型的用户） |

> 同一作用域内默认模型**互斥**（有且仅有一个默认）。把自有模型设为默认时会清除「首选全局模型」指针，把全局模型设为默认时会写入用户首选指针。

### 3.2 单次调用时选择模型（运行时选择）

| 页面 | 入口 | 传参 |
|------|------|------|
| 小程序 · 知识库问答 | 顶部「调用模型」选择器 | 请求携带 `model_id` |
| 小程序 · 智能客服 | 顶部「调用模型」选择器 | 请求携带 `model_id` |
| 小程序 · 写文章（AI 辅助撰写） | 「调用模型」选择器 | 请求携带 `model_id` |
| 管理端 · AI 配置 → 模型列表 | 每行「测试」按钮 | 仅测试该模型连通性 |

- 页面内选择器默认选中：**本地上次选择 → 我的默认 → 全局默认 → 列表中第一个**。
- 选择结果写入本地缓存 `ai_selected_model_id`，下次进入自动恢复。
- 未配置任何模型时，选择器显示「未配置模型，去添加」，点击跳转 AI 配置页。

## 四、默认模型与调用解析顺序

一次 AI 调用实际使用的模型，按以下优先级解析（`ai_models.resolve_model`）：

1. **请求显式指定的 `model_id`**（且该模型启用、属于全局或调用者本人）
2. **功能级配置为该功能指定的模型**（`ai_config.feature_config[功能].model`，管理员在「AI 功能级配置」中选择）
3. **调用者的用户默认模型**（首选全局模型指针，或本人默认模型）
4. **全局默认模型**
5. **兼容兜底：旧版全局单配置**（`ai_config` 顶层 `apiKey/apiUrl/model`，保证历史行为不中断）

补充规则：

- 显式指定的模型若**不存在 / 已禁用 / 无权访问**，会自动回退到下一级，并在日志中告警，避免因模型被删除导致调用直接失败。
- **功能级配置**的 `model` 解析规则：
  - 命中「AI 模型列表」中**已登记的模型** → 该功能固定使用该模型（无论按模型 ID 还是按模型标识 / 名称填写均可命中）；
  - 命中的模型**已禁用** → 不生效、也不回退为「按名称覆盖」，最终走 3 → 4 → 5；
  - 未命中任何登记模型 → 视为**旧版「模型名称覆盖」**，仅在旧版兼容模式下参与调用（一旦登记了模型条目，为避免「模型名与供应商不匹配」，名称覆盖不再生效）。
- 功能级配置的 `temperature` / `max_tokens` 始终叠加生效。
- 业务服务无需显式传参：`call_llm_with_fallback` 会自动以服务自身的 `SERVICE_NAME` 作为功能名参与解析，确保功能级选择真正生效。

## 五、配置生效时机

> **保存后立即写入数据库，下一次 AI 调用即生效，无需重启服务。**

- 系统每次调用 AI 时都从数据库实时解析配置，不存在进程内缓存，因此**新增 / 编辑 / 禁用 / 切换默认模型**在**下一次调用**立刻体现。
- **缓存按模型隔离**：AI 结果的缓存哈希会自动纳入「当前生效模型」签名。因此 **同一内容切换模型后不会命中旧模型的缓存结果**，会重新调用新模型生成。
- 旧版单配置（未登记任何模型条目）仍保留原有「按分级覆盖模型参数」的行为。

## 六、安全说明

- **API Key 服务端保存**：列表接口仅返回脱敏值（`****` + 末 4 位），明文 Key 不下发到前端。
- **小程序不再直连 LLM**：AI 调用统一经后端转发，Key 不落到小程序本地，也不再受微信请求域名白名单限制。
- **越权防护**：用户仅能编辑 / 删除自己的模型；仅能选择「全局模型」或「本人模型」。
- **SSRF 防护**：API 地址仅允许 `http/https`，并拒绝内网 / 回环 / 保留地址。

## 七、接口清单

### 管理端（需管理员令牌 + `ai.config` 权限）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/ai/models/` | 全局模型列表 + 元信息（上限 / 预设 / 默认 / 说明） |
| POST | `/api/admin/ai/models/` | 新增全局模型 |
| GET | `/api/admin/ai/models/meta/` | 数量上限、预设、默认模型、解析顺序、生效说明 |
| PUT / DELETE | `/api/admin/ai/models/<model_id>/` | 更新 / 删除全局模型 |
| POST | `/api/admin/ai/models/<model_id>/default/` | 设为全局默认 |
| POST | `/api/admin/ai/models/<model_id>/test/` | 测试该模型连通性 |

### 小程序端（需 `X-Openid` 请求头）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/ai/models/` | 可用模型列表（全局 + 本人）+ 元信息 |
| POST | `/api/ai/models/` | 新增本人模型 |
| GET | `/api/ai/models/meta/` | 元信息 |
| PUT / DELETE | `/api/ai/models/<model_id>/` | 更新 / 删除本人模型 |
| POST | `/api/ai/models/<model_id>/default/` | 设为我的默认（自有模型或全局模型） |
| POST | `/api/ai/models/<model_id>/test/` | 测试连通性 |

### 携带模型选择的业务接口

- `POST /api/ai/assist/`（写文章）—— 可选 `model_id`
- `POST /api/ai/kb-ask/`（知识库问答）—— 可选 `model_id`
- `POST /api/ai/cs-chat/`（智能客服）—— 可选 `model_id`
- `POST /api/admin/ai/test/` —— 可选 `model_id`（测试指定模型，无需先启用全局开关）


## 九、常见问题

**Q：用户没有任何自有模型时能用 AI 吗？**
A：可以。会依次使用「用户默认（若有）→ 全局默认 → 旧版单配置」。管理员只要配置了至少一个启用的全局模型即可。

**Q：为什么切换模型后回答和上次不一样了？**
A：这是预期行为。缓存按模型隔离，切换模型会重新调用新模型。

**Q：模型测试与全局「启用 AI」开关的关系？**
A：模型列表中的「测试」不受全局开关限制，便于在正式启用前先验证 Key 是否可用；但业务 AI 能力仍受全局 `enabled` 开关控制。

**Q：改了上限不生效？**
A：`AI_MODEL_LIMITS` 在启动时读入，修改后需重启后端进程。

**Q：全局模型的 Key 会被小程序用户看到吗？**
A：不会。接口仅返回脱敏值，明文 Key 仅存服务端。
